# 首版验收标准

## 自动检查

- `python scripts/build_skill.py --check`：全量文件与目录、SHA-256 清单一致；没有省略官方模块。
- `npm ci` 成功，Remotion 相关包均固定在 4.0.535。
- `npm run check`、`npm test` 通过。
- `npm run render` 输出 H.264、yuv420p、1920×1080、60 fps、900 帧、15.000 秒的 `out/pulse.mp4`。
- `python scripts/verify_video.py examples/pulse/out/pulse.mp4`：元数据、帧数、无音轨约定与完整解码通过。
- 视差小样 360 帧/6 秒，遮罩小样 240 帧/4 秒；同样 1080p60。
- VECTOR 同为 900 帧/15 秒/1080p60，无声。镜头目的地、移动中点和最后一帧需抽样检查；相机焦点始终投影到画面中心。第 720 与 899 帧绘图调用一致，形成稳定尾帧。
- 不提交 node_modules、临时缓存、凭据；公开内容保留来源与许可范围。

## 画面检查

检查第 0、120、290、300、420、590、600、720、899 帧，再检查运动段。

- 三个阶段能辨认；交叠转场没有突然黑帧。
- 粒子能聚成环，高速隧道保持中心焦点，最后回到轨道结构。
- 字体已加载，页边注释完整；画面无意外剪裁或遮罩泄漏。
- 视差循环边缘连续；反向或任意跳帧不会显示前一帧残影。
- 遮罩只裁切自身轨迹，标题和其他图形保持完整。
- 首尾黑场属于计划内淡入淡出；禁止把设计黑场当作渲染失败。
- 主片与小样均为无声。首版不含旁白、音乐和外部媒体。

## 结果留证

实际执行结果记在 `docs/validation.md` 与 `docs/validation-v2.md`。截图可确认构图，元数据可确认格式，完整解码可确认编码没有损坏；它们不能替代真人对连续运动、播放设备性能与音质的判断。尚未做的检查必须明确写出。
