# Waterline · 海面真实感校正

浏览器原生 ES Modules / Three.js 0.183.2 / WebGPU / TSL。入口为 [index.html](index.html)，海面、天空、后处理与自适应性能逻辑集中在 [main.js](main.js)。

在仓库根目录执行 `python3 -m http.server 8000`，打开 <http://localhost:8000/waterline/>。需要支持 WebGPU 的浏览器及 unpkg.com 访问能力；线上运行使用 HTTPS。

## 2026-11-18：基于最新版本的小范围校正

基线为 `b214dd24e111e993d3ea97c75bb955148a097aed`（2026-11-15，Improve Waterline ocean reflection, wave detail, and whitecaps）。以下三项来自当前代码路径分析；本次环境无法生成实际渲染画面，视觉改善仍需在可用的 WebGPU 设备上确认。

| 具体问题与位置 | 本次改动 | 预期影响 |
| --- | --- | --- |
| `waterColor` 的反射方向使用全域软抬升，连本已高于地平线的反射光线也被抬高；地平线下的邻浪固定只保留 16% 天空光。原实现虽已连续，仍可能产生方向偏移和偏暗的掠射角色带。窄太阳高光也未计入剩余法线的像素内变化。 | 抬升限制在反射足迹范围内，用值及斜率连续的二次过渡接回原始方向；邻浪复用 IOR=1.333 的水面 Fresnel；把 `fwidth(normal)` 估计的剩余方差加入既有粗糙度。 | 有效天空反射方向得以保留，掠射角邻浪亮度随入射角变化；抑制亚像素高光闪烁。 |
| `foamLight` 用叠加细波后的 `sunFacing`，并带有不随朝向消失的太阳项；白沫光照随小波纹变化。远处白沫细节已混到平均覆盖率，仍执行一次无贡献的破碎噪声。 | 白沫的太阳漫反射使用 Gerstner 波面法线和同一太阳方向、颜色与昼夜权重；天空项按波面朝向调制。只有可分辨的白沫才采样破碎噪声，远处沿用平均覆盖率。 | 白沫跟随浪面受光，背光面不再额外接收该太阳常量；保留破碎纹理并减少远处无效计算。 |
| `waterColor` 的固定雾密度 `0.00165 m⁻¹` 使一公里处约 81%、两公里处约 96% 的水色被替换，过早压平中远景。 | 密度改为白天 `0.00024` 至暮色 `0.00038 m⁻¹`，随既有太阳状态连续变化；继续使用同一天空函数作雾色。 | 保留中景反射和起伏，在 14 公里网格外缘仍渐近天空颜色。 |

## 后处理与性能

已读取并检查 `start()` 中的后处理链：线性 HDR 场景输出 → Bloom → 暗角 → RenderPipeline 的单次 ACES 与 sRGB 输出转换。维持曝光 `1.02`、Bloom 参数 `0.27 / 0.45 / 1.28`；固定版本的 Bloom 本身从半宽、半高缓冲开始。本次没有新增渲染通道、纹理或波浪层，也没有提高分辨率。

| 预算 | 桌面 | 触屏 |
| --- | ---: | ---: |
| 网格环数 × 辐条 | 192 × 320 | 144 × 224 |
| 顶点 / 三角形 | 61,441 / 122,560 | 32,257 / 64,288 |
| 绘制像素上限 | 2,850,000 | 1,250,000 |
| AUTO 目标帧率 | 60 | 30 |

上述预算及原有动态降分辨率、后台暂停、GPU 待完成帧限制均保留。新增成本主要是法线导数、Fresnel 和少量标量运算；远处不可分辨的白沫跳过噪声，但不据此声称整体帧率提升。所有新增屏幕导数位于逐像素条件分支之外。

## 本轮验证记录

- JavaScript 模块语法与 `git diff --check` 通过。语法复现：在仓库根目录执行 `node --input-type=module --check < waterline/main.js`。
- 使用 Three.js **0.183.2** 和 `webgpu`（Dawn Node）**0.6.2** 的 **Null 后端**，分别为原版 / 修改版生成桌面与触屏网格，并通过真实的 `WebGPURenderer.compileAsync()`、后处理管线提交和 WebGPU validation error scope 验证。四组海面、天空及 HDR/Bloom/ACES 管线均未报告验证错误。Null 后端验证不包含像素光栅化或帧率测试。
- 对地平线过滤及邻浪 Fresnel 作 100,005 个标量采样：结果有限、范围合理；过滤单调，足迹范围外保留原方向，过渡端点斜率匹配。核对了上表雾比例。
- 浏览器能加载入口与固定版本模块，但 `requestAdapter()` 返回空；本机原生 WebGPU 也没有可用光栅化适配器。因此前后截图、真实 GPU 画面、移动端帧率与热稳定性**未实测**。

设备上复核时使用默认 46% / 17:33 观察掠射角反射，再将海况调至 80–100%，在正午、日落及午夜检查白沫随光照变化；缩放、旋转确认中远景过渡与太阳高光稳定。手机使用 AUTO 并旋转横竖屏，观察数秒后的稳定帧率和分辨率收敛。

本轮维持解析海洋与近似邻浪反射；没有新增屏幕空间反射、反射光线追踪或泡沫历史模拟。

实现依据：[Three.js RenderPipeline](https://threejs.org/docs/pages/RenderPipeline.html)、[固定 r183 Bloom 源码](https://github.com/mrdoob/three.js/blob/r183/examples/jsm/tsl/display/BloomNode.js)。

## 离线体积云与更高精度单帧

[离线渲染器及完整参数](offline/README.md)增加了三维云密度、自阴影、天空遮挡、同源倒影与海面云影，以及六组细波纹。默认使用原网页 256 倍网格采样量、64 个固定时刻子像素样本和 7680 × 4320 输出；渲染器会自动使用 32 位索引。
